## Connection-count caution

The initial script counts outgoing edges in the `connections` JSON. Several files with many nodes have zero or unexpectedly low edges. This is a strong warning, not proof of invalidity: n8n connections can have multiple output shapes and the parser must be validated against the full schema. Before any candidate is labelled functional, validate the graph using n8n-compatible parsing and an isolated test instance.

## Licensing and security

The repository's [LICENSE](https://github.com/Zie619/n8n-workflows/blob/main/LICENSE) is MIT. The candidate metadata also frequently labels files MIT. Before commercial adaptation, preserve applicable notices and independently check all embedded assets, prompts, code provenance, third-party API terms and any source material. Do not import any candidate with credentials or execute any Code/Function/Execute Command/HTTP node before static inspection.

## Preliminary conclusion

**No candidate above is approved for direct production import.** The best value is selectively reusing simple node patterns (manual trigger, binary read, PDF text extraction, image resizing, Convert to File, Drive storage) inside a new, small, tested KKAM workflow. The production PDF factory should be implemented primarily as custom code with explicit validation and approval gates, rather than depending on these placeholder-heavy examples.
